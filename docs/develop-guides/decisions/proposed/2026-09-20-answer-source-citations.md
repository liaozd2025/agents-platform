# 主子智能体回答引用与原文查看

状态：proposed
类型：bug-fix
Owner：backend/package/yuxi/agents/buildin/chatbot/prompt.py

## 问题

用户观察到事实核查员回复带引用标识，而主助手汇总回复缺少标识。目标是让主回复保留实际采用的引用，使用与子回复一致的标识样式，并能点击查看原文。

源码检查确认：事实核查员的角色提示词要求生成 `<cite>`；共用提示词构建函数没有启用已定义的引用规则。主回复和子任务结果共用 Markdown 展示组件，该组件有引用样式但没有引用点击处理。子任务返回最终正文和运行信息，未携带稳定绑定的原文证据。上述结果属于源码检查，尚未复现用户报告的具体会话。

本文供实现者与 Reviewer 使用，记录引用展示与证据交接的提案；术语见仓库根目录 `CONTEXT.md`，不涉及发布或生产数据修改。

## 提案

已确认的用户行为：主回复只在实际采用的结论旁保留引用，并在该回复内统一编号；主子回复采用相同的标识样式；点击后弹窗显示引用原文片段、来源标题，以及打开完整文档或网页的入口。

实现方向：复用现有 Markdown 展示组件与来源预览能力，沿检索结果、子任务回传、主回复和消息保存传递来源身份与真实片段。提示词负责要求引用，程序负责把标识绑定到已取得的来源。编号只属于当前回复的展示顺序，来源身份不能依赖子智能体生成的数字或文件名。

行为分工：`backend/package/yuxi/agents/buildin/chatbot/prompt.py` 拥有共用回答约束；`backend/package/yuxi/services/agent_run_service.py` 与 `backend/package/yuxi/agents/middlewares/subagent_task.py` 拥有子结果交接；`backend/package/yuxi/services/chat_service.py` 拥有最终消息保存；`web/src/components/common/MarkdownPreview.vue` 与 `web/src/components/AgentMessageComponent.vue` 拥有引用展示和交互。同步、异步和恢复路径采用同一引用语义。

已确认的缺失处理：只有来源链接、没有原文片段时，保留引用标识；弹窗明确提示“未获取到原文片段”，并提供来源链接。智能体摘要不能作为原文展示。

已确认的历史范围：新回复完整支持上述行为；历史回复按已有标识和来源数据展示，缺少引用的旧正文保持原样，不自动补做引用或改写历史消息。

## 替代方案

- 仅启用引用提示词：改动小，但无法保证标识可以定位真实原文，不满足点击查看的验收要求。
- 原样拼接子智能体回复：能保留文本标记，但重复编号和未采用资料会混入主回复，不符合已确认的编号规则。
- 复用已有展示与来源能力，补齐证据交接：作为拟采用方向，增加的绑定和保存逻辑仅服务于实际引用及其原文查看。

## 风险

网页搜索返回的摘要不一定是可核对的原文，来源链接本身也不能证明已取得原文。文件名和子任务局部编号都不足以唯一定位证据，多个子任务汇总及长结果压缩必须保留稳定来源关联。历史消息能展示的内容受已保存数据限制；缺少片段时明确提示，缺少标识时保持旧正文。
