# 主智能体与 PI 的阶段委派及资源开销

状态：implemented
类型：architecture
Owner：backend/package/yuxi/agents/middlewares/pi_sandbox.py

## 问题

医院模板及格式随输入变化，Skill 规定执行流程。连续工作拆成多次 PI 委派会重复传递上下文、读取文件和核验，隐式续接最近一次 PI 又会被插入的独立任务改变来源。优化按任务总耗时、Token、资源占用排序，并保留交付质量、权限隔离与可取消性。

## 决策

主智能体负责用户沟通、知识检索及阶段安排；PI 连续执行一个由任务和 Skill 定义的阶段，包括输入检查、处理和产物核验。主智能体交齐已知路径、必要证据、约束和验收要求，长资料引用当前已授权且 PI 可读的项目文件。知识库文件身份仍需经授权读取转换成可交接内容。

PI 返回简短结论、原始产物路径、验收依据和未解决项；文档任务把核验过的关键内容写入可读取的文本。主智能体核对内容和证据，发现具体缺项、矛盾或新增要求才追加委派；阶段边界不固定医院模板。产物使用既有登记路径，避免为交付重复复制文件。

已知用户文件的 `read_file` 复用 Workspace 的 no-follow、有界普通文件读取，不创建沙箱；超过既有预览字节上限或需要解析二进制文档时交给 PI。读取与分页使用一致的 Unicode 行定义，只在实际存在后续内容时返回续读偏移。路径权限由 backend 与 Workspace 最终执行。

`source_run_id` 省略时新建上下文，指定时续接同用户、Project、对应子会话中已完成且在当前 child 创建前 ACK 的来源。工具结果向父模型返回本次 Run 和实际来源。失效来源明确失败；session 快照继续验证完整性。旧 `continue_session=true` 单独出现时按原时间边界选择最近合格来源，找不到时返回错误；false 与显式来源冲突，true 与显式来源并用时采用显式来源。旧持久记录缺少开关时保留原自动续接语义。幂等重放使用原 child，已有 attempt 的 manifest 固化来源及其引用，禁止重绑。

每次委派仍启动一次 PI 进程，续接通过已校验的历史快照实现。同根运行按原规则复用沙箱，等待用户或根任务终态后清理，项目文件保留。`runtime inspect` 直接校验版本、锁文件、Runner 与 Skill 摘要，实际任务才加载 SDK；不引入缓存、进程池或容器常驻。运行机制与各语义 Owner 见[沙箱机制](../../../mechanisms/sandbox.md)。

计时由登记 service、执行 service、Runner 和 worker 分别记录；流式执行记录输出轮询、轮询 API 调用（不含 SDK 内部重试）、空输出和传输字节。用户等待单列，父任务总耗时包含子任务，不重复相加。容器资源来自定时采样，仅作为所测任务的样本峰值。

## 替代方案

- 由 PI 接管知识检索和用户沟通：需要扩展授权和编排边界，当前阶段交接已复用现有能力。
- 每次重新开始或总是续接最近 PI：分别丢失编辑历史或错误继承独立核验，采用显式 Run 来源。
- 父每次再委派全量检查：增加往返，采用关键内容回读与具体缺项触发追加工作。
- 常驻进程、等待期间保留容器、容器池或跨次缓存：增加生命周期和失效规则，当前消除 inspect 无效 SDK 加载已无需这些机制。

## 后果

父模型可以直接核对已知文本，执行阶段仍受既有模型与时间预算约束；预算耗尽和 Run completed 均不代表业务验收。大文本采用现有读取上限，超过上限显式要求 PI 提取，未增加流式文件读取接口。相同 Skill 摘要仍保留登记、执行及 runtime 检查；本次样本的摘要计算耗时不足以支持新增缓存。

提示词不能保证所有模型只委派一次，长阶段也可能消耗更多模型预算。真实模型时延和缓存命中存在波动；结论仅适用于记录的两种合成模板，不外推医院模板覆盖率、生产服务或并发容量。

## 验证

行为证据由现有 system-tests workflow 直接执行的 HTTP PI E2E 持有：两组 A 编辑、B 独立核验、C 续接 A 的序列；伪成功摘要对应实际缺项后追加定向修正；缺资料时父询问并清理运行资源、用户通过 resume 补充值后续接原 PI 且回读真实文件。原大文件交付、旧布尔输入续接、运行中引导和取消也通过。

真实 PostgreSQL 的 Run/attempt 测试覆盖明确来源、同用户与子会话、完成和 ACK、时间界限以及 final 重放；unit 覆盖冻结引用变化、session 字节完整性、冲突参数和原 child 幂等。冻结引用比较删除后，负向用例以“未抛出预期错误”失败。Workspace 实际文件测试覆盖同步/异步 Unicode 分页、EOF、符号链接、字节上限和关闭后的读取；Unicode 旧实现先复现漏行，再验证修复。

Node 的实际 SDK/Runner 测试通过，inspect 路径在禁止加载 SDK 的条件下仍完成摘要检查。另五项真实 Local sandbox 测试覆盖取消停止写入、回收运行域、流式回调取消和大小写 Skill 树摘要。未改变轮询间隔、退出确认、授权和终态规则。

完整非 slow unit 在临时容器中为 2012 passed、45 skipped，另有基线相同的四项失败：三项 OA 测试实际依赖 PostgreSQL，单独使用真实数据库通过；一项 user_config router 测试的模块名遮蔽错误在原基线同样失败。没有扩大修改范围修复该既有问题。

干净 `c36e495f` 与候选在隔离环境中，使用同一 Skill、固定输入、PI SDK 0.84.2 和 DeepSeek V4 Flash 参数，分别运行两种结构的合成模板各三次。12 次交付的正文、模板样式、页眉页脚与证据值均独立回读通过。统一 oracle 仅归一化 python-docx 自动创建的完全无内容页眉引用及未启用的首/偶页空页脚引用；内容和格式变异有六项负控。耗时包括请求提交至终态及根清理，未发生用户等待；三次原始值同时给出范围。
