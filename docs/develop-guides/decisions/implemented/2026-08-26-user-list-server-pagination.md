# 用户列表服务端分页

状态：implemented
类型：bug-fix
Owner：backend/server/routers/auth_router.py

## 问题

用户管理页面为了得到总数，在浏览器内循环请求全部用户页。用户规模较大时，首屏需要等待全部请求结束，且加载状态长时间不消失。

## 决策

`GET /api/auth/users` 继续返回用户数组以保持已有调用方兼容；在 `X-Total-Count` 响应头返回授权和筛选后的总数。前端每次只请求当前页，并在翻页、修改每页数量或改变筛选条件后请求对应页面。关键字、组织和角色筛选在授权过滤之后由服务端执行，避免筛选退化为只检查当前页。

## 替代方案

- 将响应体改为 `{ items, total }`：拒绝，会破坏当前依赖数组返回值的调用方。
- 前端继续全量拉取再分页：拒绝，首屏延迟和多次请求会随用户规模线性增长。
- 仅对当前页做筛选：拒绝，会改变已有筛选语义并得到不完整结果。

## 后果

跨域部署时需显式暴露 `X-Total-Count`，否则浏览器无法读取总数。当前授权范围仍由 `list_authorized_users` 确定；后续若目录规模继续增长，可在不改变 HTTP 契约的前提下将筛选和分页下沉到仓储查询。

## 验证

- 真实 HTTP 集成测试验证页大小、下一页为空时的总数稳定性和关键字筛选。
- 前端单元测试验证一次调用只产生一个带分页参数的请求，并读取 `X-Total-Count`。
- 前端构建和真实页面验证首屏与翻页请求数量。
