# 保留不兼容的 Milvus 集合

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/knowledge/implementations/milvus.py

## 问题
集合初始化由查询、入库和分块更新共用。旧实现遇到模型描述不匹配或缺少 BM25 schema 时直接删除集合，导致 PostgreSQL 仍显示 indexed，而向量数据已经丢失。

## 决策
已有集合不兼容时显式报错，保留全部数据。集合不存在时仍按既有路径创建。历史空描述也不自动推断模型身份。集合初始化不负责数据迁移；需要恢复时从保留的正文重新生成向量，并核对真实数据。

## 替代方案
自动重建会丢数据；仅按维度接受未知模型无法证明向量空间一致。选择保留数据并要求显式迁移。

## 后果
不兼容旧集合停止使用，需显式迁移。既有调用方仍按自身错误契约报告初始化失败。移除错误的 connections.MilvusException 引用，避免异常处理反而掩盖原始错误。兼容集合与新集合的原有路径不变。

## 验证
- 容器内 test/unit/plugins/test_milvus_kb.py：21 项通过。新增空描述、不同模型、缺少 BM25 三个负向案例；原实现三项失败。
- 真实 Milvus 临时集合写入一条记录后，调用初始化触发模型不匹配；重新读取确认集合仍存在且记录数仍为一，随后清理该临时集合。
- 恢复的数据验收必须比较 PostgreSQL 正文与 Milvus 实际记录，并执行真实模型检索；文件表的 indexed 状态不作为向量数据完整性的证据。
