# 合并后的资源初始化与执行授权契约收敛

状态：implemented
类型：bug-fix
Owner：backend/yuxi/modules/extensions/skills/builtin/sync.py

## 问题

内置 Skill 首次安装持久化旧版平铺共享配置，当前权限解析要求 version 2，导致已选择知识库的 Agent 没有检索 Skill 和工具。再次同步写入 v2，会掩盖首次安装缺陷。部分输入与协作入口直接查询用户标量字段，缺失组织祖先链；MCP 通用封装覆盖专用客户端工厂，使内部服务连接丢失代理隔离策略。

## 决策

### 实现方案

首次安装使用已有 Skill 共享配置规范化入口；现有内置技能通过原有同步入口恢复标准配置并保留启停状态。输入创建、后续 Input 和协作目录/创建复用 UserRepository 读取角色及组织链，继续拒绝缺失或已删除账号。MCP 同源保护包装已有客户端工厂，保留内部知识服务的 trust_env=False 及既有请求钩子；未提供工厂时使用 SDK 默认工厂。

## 替代方案

不放宽权限解析以兼容任意旧格式，不让检索绕过功能权限和资源共享范围，不用提示词掩盖工具装配缺失。内部 MCP 保留现有 HTTP 同源约束。

## 后果

内置技能首次创建与再次同步遵循同一契约；普通用户资源及角色分配不被改写。已经构图的执行需要停止后重新发起，才能使用修复后的装配。用户读取多加载授权关系，避免部门共享智能体被误判不可见。

## 验证

- test/integration/services/test_builtin_skill_authorization.py：首次真实 PostgreSQL 安装、知识技能预加载、旧格式重同步与禁用状态保留；修复前首次安装不可用，修复后通过。
- test/integration/services/test_agent_department_access.py：独立会话中的创建、追加输入、协作目录和创建；部门内可见、跨部门及删除账号拒绝；4 个正例先失败，修复后 11 项通过。
- test/integration/mcp/test_http_origin.py：不可达代理环境下实际 MCP 发现与调用成功，自定义客户端钩子保留且跨源重定向被拒绝；两个新增负例先失败后通过。
- 后台作业补投递测试显式覆盖 1、4、10 个 worker 槽对应 1、3、4 的后台容量，避免测试把固定常量误作当前部署容量。
- 本地真实模型与 ARQ worker 经知识库 MCP 完成一次问答，回读 Run 完成终态及工具审计：直接检索成功，无协作子会话。该样本不是全量模型、全部资源类型或压力测试的替代。
