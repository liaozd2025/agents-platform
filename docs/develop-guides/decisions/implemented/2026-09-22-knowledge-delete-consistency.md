# 知识删除以实际存储完成为准

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/knowledge/implementations/milvus.py

## 问题

删除路径吞掉向量和图清理失败后仍删除 PostgreSQL 元数据；文件夹递归绕过路由中的对象清理。结构已写而向量未完成的图中间态被完成标记过滤，图引用先提交删除也会丢失重试所需的对象标识。

## 决策

在知识执行器收敛单文件对象、向量和图清理，让递归与 HTTP 使用同一路径；实际清理失败向调用者传播，保留能够重试的 PostgreSQL 文件及 chunk 元数据。图引用事务在外部幂等清理成功后提交，失败回滚保留重试依据；删除文件和整库时直接清理 Neo4j，覆盖完成标记尚未写入、甚至 PostgreSQL 图引用尚未写入的中间态；普通重索引按图标记或引用判断，不新增无图重索引的 Neo4j 依赖。整库删除确认各存储清理成功后才移除主记录。复用现有异常、事务及存储方法，不新增队列、状态表或配置。

## 替代方案

异步墓碑及清理队列能支持长期后台重试，但增加新的业务状态与 worker 职责；现有同步接口与保留元数据的显式重试已足够。仅让路由抛错无法覆盖递归、更新索引及图引用先提交造成的残留。

## 验证

`backend/test/e2e/knowledge/run_delete.sh <API_IMAGE> <PROVISIONER_IMAGE>` 在一次性 Compose 中通过实际 HTTP、PostgreSQL、MinIO、普通及图 Milvus 集合和 Neo4j 回读，包含失败恢复、文件夹递归、图中间态、共享实体与整库清理；既有共享图删除 integration 同时通过。原 main 和两项单独恢复缺陷的变异均在对应业务断言失败。完整 backend unit 为 2346 passed、53 skipped。未验证生产环境。

## 后果

多存储操作不是分布式原子事务：失败时部分外部对象可能已移除，接口明确失败并保留重试依据。图引用事务在外部清理期间持有数据库事务；只处理当前文件，不并发扇出。文件及整库删除需要 Neo4j 可达：缺少图标记不能证明没有早期写入，连接失败会明确阻止成功结果。单文件保留可能共享的解析图片，整库按知识库前缀清理。范围限本地隔离环境，不访问生产或付费模型。
