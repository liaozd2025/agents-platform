# 知识库检索范围路由

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/knowledge_retrieval_policy.py

## 问题

聊天请求需要在不影响普通问题延迟的前提下使用全局知识库，并尊重用户明确的知识库 `@` 范围。

## 决策

- 消息包含 `@knowledge` 时，只检索被引用且当前用户有读取权限的知识库。
- 消息未引用知识库时，明显的闲聊、翻译、润色和简单计算跳过检索；其余问题检索当前用户可读且 `read_scope.access_level=global` 的全部知识库。
- 全局知识库按请求动态读取，不保存固定 `kb_id` 列表，因此新增全局只读知识库会自动生效。
- 多个目标知识库并行检索，结果仅追加到本轮模型输入，不写入用户历史消息。

## 替代方案

固定保存全局知识库 ID 会遗漏后续新增的共享库，因此按请求读取可见集合。非检索请求也先读取该集合会增加数据库依赖；采用先判定能力和非检索意图、再惰性加载知识运行时的顺序。

## 后果

该策略不改变知识库权限和现有工具；复杂意图先按“需要检索”处理，降低漏检风险。LITE 模式直接返回空检索决策；完整模式的非检索请求不查询知识库数据库。

## 验证

单元测试覆盖 `@` 优先、动态全局集合和非检索请求不访问数据库；fresh-process 测试同时验证 LITE 导入与请求路径均不加载知识运行时。
