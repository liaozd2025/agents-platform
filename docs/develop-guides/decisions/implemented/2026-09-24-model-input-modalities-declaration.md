# 模型输入模态声明驱动图片预路由

状态：implemented
类型：feature
Owner：backend/package/yuxi/models/providers/service.py

## 问题

依靠拒图错误兜底会多发一次失败请求。既有 input_modalities 可以表达模型能力，但部分供应商不提供远端能力数据，需要人工或内置模板声明。

## 决策

初始化内置模型时只为缺失或空 input_modalities 补默认值，保留管理员已有非空声明。声明非空且不含 image 时，chat_service 在 worker 固化的 context.model 下先转述本轮全部图片；含 image 时直接送主模型；空声明为未知，由中间件拒图兜底。

明确声明优先于进程内拒图学习缓存。管理员将未知模型更新为支持 image 后，下一次请求恢复直传，不等待十分钟缓存过期。本决定补充[视觉转述兜底](2026-09-23-vision-model-transcript-fallback.md)，不改变用户权限与持久化消息。

转述调优只适用于 OpenAI 兼容客户端，附 max_tokens=1000 与 extra_body.enable_thinking=false；其他客户端普通调用。带参数失败后普通调用重试一次并记录该 spec，避免反复发送不兼容参数。此重试也可能由网络错误触发。

不提供文件路径模糊改写。完整路径前缀可能使 salary.csv 与 report.csv 的相似度超过 0.9，不能作为访问另一文件的可靠依据；转述与 read_file 均保留输入路径，由工具或模型显式纠错。

## 替代方案

- 完全依赖远端 /models 元数据：部分供应商不返回能力。
- 全部带图请求强制转述：跳过原生视觉能力，增加成本。
- 用学习缓存覆盖人工声明：更新声明后仍不能立即恢复能力。

## 后果

新增模型默认未知；内置声明与人工声明需随供应商升级复核。本次只消费已有配置，不扩展前端编辑机制。转述可能丢失细节，其文本明确带来源，原始图仍在持久化消息及本轮 Workdir 文件中。

## 验证

- provider service 单测验证只补空值、不覆盖管理员与未登记模型，重复初始化无变化。
- image_input_service 单测验证声明边界与管理员更新覆盖拒图学习。
- run_inline_images.sh 本地 1 passed：支持 image 的模型一次收到两张原图；text-only 模型一次收到文本且未拒图；未知模型先拒图、转述后成功。回读模型 wire 验证实际次数、图片块和路径，视觉出站签名通过校验。

未验证：当前真实 DashScope 行为、浏览器模型管理页保存后生效与生产部署；2026-09-23 的作者实验只作为历史动机，不代表本次验收。
