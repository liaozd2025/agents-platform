# S0：OA 嵌入链路实施设计（2026-08-12）

## 目标

让 Yuxi 以 iframe 插件形式嵌入 OA，用户从 OA 免登录进入即可对话；OA 侧只需加一个菜单项和一个 `<iframe>`，不引入任何前端框架依赖。

## 验收标准

一条端到端闭环，在 400px 和 1920px 两种 iframe 宽度下都成立：

1. 从模拟 OA 页面 iframe 加载 Yuxi，页面正常渲染，无侧边栏/顶栏
2. 走 OIDC 完成免登录，**全程不出现 Yuxi 登录框**
3. 发起一轮对话，看到流式输出
4. 产生一个产物，能下载
5. 窄档点「展开」→ 父窗口收到 `yuxi:expand` 且带 `threadId`
6. token 过期 → 父窗口收到 `yuxi:auth-required`，重新下发 token 后对话可继续

## 前置阻塞与假设

**阻塞**：OA 团队尚未提供 OIDC discovery 地址与 client 凭据。

**绕开方式（必须按此执行，不要自行编造 OA 地址）**：本地起一个模拟 OIDC Provider，用它跑通全链路。OA 信息到位后**只改环境变量，不改代码**。

现有配置已支持两种模式（`oidc_service.py:191-202`）：配了 `OIDC_AUTHORIZATION_ENDPOINT` 就用显式端点，否则走 `OIDC_ISSUER_URL` 的 discovery。模拟 Provider 用 discovery 模式即可。

**其他假设**（OA 确认后可能需要调整，代码里不要写死）：
- OA origin：用环境变量 `YUXI_EMBED_ALLOWED_ORIGINS` 配置，不写死
- 部门 claim 名：用现有 `OIDC_DEPARTMENT_CLAIM` 配置项，不写死
- 部署为同主域子域（`oa.corp.com` / `ai.corp.com`），故不处理 localStorage 分区

## 范围边界（明确不做）

- 不做组织架构同步、不做权限同步（已确认「仅身份 SSO」）
- 不做 `tenant_id` / 多租户改造（已确认「一个 OA = 一个租户」，见可行性分析第八节）
- 不统一现有 13 个散落的 `@media` 断点（大面积改现有代码，与 vendor fork 的 rebase 成本冲突）
- 不补 46 条知识库路由的 authz（属于 S2，独立任务）

## T1 · 允许被嵌入

**改动**：`docker/nginx/default.conf`

在 `location /` 加响应头：

```nginx
add_header Content-Security-Policy "frame-ancestors 'self' ${EMBED_ALLOWED_ORIGINS}" always;
```

取值来自环境变量，经 compose 传入；默认值为 `'self'`（即默认不可被外部嵌入）。

**注意**：当前 nginx 与 FastAPI 都没有设 `X-Frame-Options` 或 CSP，任何站点都能 iframe 本系统。**不要只加白名单就算完** —— 这一条同时是在修一个现存的点击劫持漏洞，配置缺省时必须是拒绝而不是放行。

**CORS**：`YUXI_CORS_ORIGINS` 加入 OA origin（`backend/server/main.py:44` 已支持，无需改代码）。

**验收**：非白名单 origin 的页面 iframe 加载被浏览器拒绝并在 console 报 CSP 错误。

**改动**：`web/src/router/index.js`

**验收**：`/embed` 渲染出纯对话界面，无侧边栏、无顶栏、无任务中心入口。

## T3 · postMessage 协议

**新增**：`web/src/composables/useOAEmbedBridge.js`
**改动**：`web/src/router/index.js`（guard）、`web/src/stores/user.js`

### 消息定义

| 方向 | 消息 | 载荷 |
|---|---|---|
| OA → Yuxi | `oa:token` | `{ token }` — 下发/刷新登录态 |
| Yuxi → OA | `yuxi:ready` | `{}` — iframe 已就绪，可以下发 token |
| Yuxi → OA | `yuxi:auth-required` | `{}` — 登录态失效，请求重新握手 |
| Yuxi → OA | `yuxi:expand` | `{ threadId }` — 请求切全屏并带上会话上下文 |

### 时序

```
iframe load → Yuxi 发 yuxi:ready → OA 发 oa:token → Yuxi 存 token 并渲染
token 失效 → Yuxi 发 yuxi:auth-required → OA 重新走 OIDC → OA 发 oa:token
```

`yuxi:ready` 之前不发任何请求。若 3s 内未收到 `oa:token`，渲染一个「等待 OA 授权」占位态并重发一次 `yuxi:ready`（OA 侧监听器可能晚于 iframe load 注册）；**不要跳登录页、不要渲染登录表单**。

### 安全红线（两条都必须实现，不可省）

1. **接收侧必须校验 `event.origin`** 在白名单内，否则直接丢弃。白名单来自构建期环境变量。
2. **发送侧 `targetOrigin` 绝不能用 `*`** —— 握手里传的是 token，用 `*` 等于把 token 广播给任何能 iframe 本页的站点。

### 路由 guard 改造

`web/src/router/index.js:181` 现在是：

```js
if (requiresAuth && !isLoggedIn) {
  sessionStorage.setItem('redirect', to.fullPath)
  return '/login'
}
```

嵌入态（`to.meta.embed`）下改为：发 `yuxi:auth-required`，停在占位态，**不跳 `/login`**。

> 理由：在 iframe 里渲染登录框既破坏体验，也是在训练用户接受"在第三方页面内嵌的框里输密码"，等同于钓鱼训练。

**验收**：伪造一个非白名单 origin 的父页发 `oa:token`，token 不被接受；抓包确认 `yuxi:*` 消息的 targetOrigin 是具体 origin 而非 `*`。

## T4 · OIDC 修复（SSO 成为唯一入口后，这是信任根）

**改动**：`backend/package/yuxi/services/oidc_service.py`

### 4.1 `id_token` 验签 + nonce 校验

现状：`id_token` 从不解码、从不验签，身份完全来自 userinfo 端点（`get_userinfo`）。`generate_nonce()`（:260）生成了 nonce 并发出去，但**从未验证过**。

做法（**零新依赖**，`pyjwt>=2.13.0` + `cryptography>=48.0.1` 已在 `backend/package/pyproject.toml`）：

```python
from jwt import PyJWKClient
# 用 discovery 拿到的 jwks_uri 构造 PyJWKClient
# jwt.decode(id_token, signing_key, algorithms=[...], audience=client_id, issuer=issuer_url,
#            options={"require": ["exp", "iat", "iss", "aud", "sub", "nonce"]})
# 再比对 nonce 与本次请求存储的值
```

- `OIDCProviderMetadata.load()`（:123）需一并解析 `jwks_uri`
- JWKS 要缓存但**必须可失效**（OA 轮换签名密钥时不能一直用旧的）。注意 `get_metadata()`（:182）当前的 `cls._metadata` 缓存是永不失效的，不要照抄这个模式
- nonce 随 state 一起存（见 4.2），callback 时取出比对

### 4.2 两个进程内 store 迁 Redis

`OIDCUtils` 有**两个**类属性 dict，不是一个：

| 位置 | store | TTL | 迁移后的失败模式 |
|---|---|---|---|
| `:161` | `_state_store` | 300s | CSRF 防护，多副本下校验失败 |
| `:162` | `_login_code_store` | 60s | **承载完整登录 payload**；callback 落 worker A、exchange 落 worker B 时直接登录失败 |

两个都迁到 Redis，用 `yuxi.storage.redis.manager.get_async_redis_client()`（现成）。

- key 前缀 `oidc:state:` / `oidc:logincode:`，用 Redis 原生 TTL，**删掉 `_cleanup_expired_*` 两个手工清理方法**
- 消费必须是原子的（`GETDEL` 或 Lua），保证 state 和 login_code 一次性语义
- `state` 的 value 扩展为 `{redirect_path, nonce}`

`_metadata` 缓存可以保留在进程内（幂等、可重建），不必迁。

### 4.3 部门来源

`OIDC_AUTO_CREATE_USER=true` 且默认部门写死 `"OIDC用户"`，会导致所有 OA 用户落进同一部门，使 S1 的部门隔离失效。

本任务范围内只做一件事：**用现有 `department_claim` 配置从 claim 取部门，取不到时落默认部门并打 warning 日志**。不做组织架构同步。

**验收**：模拟 Provider 用错误密钥签发的 `id_token` 被拒绝；nonce 不匹配被拒绝；启动两个 api 副本，登录仍然成功。

## T6 · OA 侧接入片段（交付给 OA 团队）

```html
<iframe
  src="https://ai.corp.com/embed"
  sandbox="allow-scripts allow-same-origin allow-downloads allow-popups allow-popups-to-escape-sandbox">
</iframe>
```

sandbox 逐条依据（已按代码核实）：

| 权限 | 依据 |
|---|---|
| `allow-scripts` | 不给则 Vue 无法运行 |
| `allow-same-origin` | 不给则 iframe 被赋予 opaque origin，**localStorage 抛异常**，token 存不了（`stores/user.js:7`），认证链路全挂 |
| `allow-downloads` | 产物下载走 `createObjectURL` + `link.download`（`AgentArtifactsCard.vue:107-110`、`AgentPanel.vue:522-525`） |
| `allow-popups` + `allow-popups-to-escape-sandbox` | 对话流里的 web 搜索结果外链（`components/sources/WebSearchResultList.vue:11`） |

**不需要** `allow-modals`（全项目无原生 `alert`/`confirm`/`print`，确认框都是 ant-design-vue 的 `Modal.confirm`）；**不需要** `allow-forms`（上传走 fetch + FormData，无 `<form>` submit）。

**给 OA 安全团队的澄清**：MDN 关于"`allow-scripts` + `allow-same-origin` 使 sandbox 失效"的警告**只适用于同源嵌入** —— 那时 iframe 脚本可访问 `parent.document` 并移除自身 sandbox 属性。本场景是 `oa.corp.com` 嵌 `ai.corp.com`，跨源，iframe 取不到 `parent.document`，无法自我解除。此组合在本场景下既安全又必需，不要因这条警告去掉 `allow-same-origin`。
