# 旧 OA 用户独立登录

本页说明通过旧 OA 用户同步进入 Yuxi 后，如何在不嵌入 OA iframe 的情况下登录 Yuxi。

## 登录方式

独立站使用 Yuxi 本地账号密码登录：

- 用户名：同步进来的旧 OA `account`，也就是 Yuxi 用户管理页面中的“用户名”。
- 密码：由 Yuxi 管理员设置的本地密码。

这个密码只用于 Yuxi，不等同于旧 OA 密码。Yuxi 不保存、读取或验证旧 OA 密码，也不能仅凭 OA 账号判断用户身份。

iframe 场景保持不变：用户从 OA 打开 iframe 后，由 OA 下发现有 token，Yuxi 服务端校验 token 并换取 Yuxi 登录态。两种入口使用同一个 Yuxi 用户，但认证凭据不同。

## 为同步用户开通独立登录

管理员按以下步骤操作：

1. 登录 Yuxi 管理端，进入“用户管理”。
2. 按旧 OA 账号搜索目标用户，确认姓名和部门无误。
3. 编辑用户，勾选“修改密码”。
4. 设置符合页面要求的 Yuxi 密码，并再次确认。
5. 保存后，通过受控渠道将临时密码单独告知用户；不要把密码写入工单、日志、群聊或文档。
6. 用户打开 Yuxi 独立登录页，使用旧 OA 账号和这套 Yuxi 密码登录。

同步脚本新建用户时会写入随机密码哈希，脚本不会输出该密码；已有用户再次同步时也不会覆盖密码。因此，新同步用户必须由管理员执行一次密码设置，才能使用独立站登录。

## 密码重置

用户忘记 Yuxi 密码时，由具备用户更新权限的管理员在“用户管理”中重新设置密码。重置后，旧密码立即失效；旧 OA 登录态和 iframe 免登录不受影响。

账户因连续输错密码被锁定时，管理员设置新密码不会提前解除锁定。用户需要等待登录页提示的锁定倒计时结束后，再使用新密码登录。

当前流程没有“用户自助找回密码”能力。不要让用户在 Yuxi 登录页提交旧 OA 密码，也不要通过 URL、浏览器存储或日志传递任何 OA token 或密码。

## 同步后的检查

完成用户同步后，管理员应从数据库或用户管理页面确认账号已存在且处于有效状态，再单独设置 Yuxi 密码。可按以下顺序验证：

1. 独立登录页使用该账号和新设置的 Yuxi 密码能够登录。
2. 登录后能够访问该用户有权限的会话和功能。
3. 从 OA 打开 iframe 时，仍能通过 OA token 自动进入同一用户，不显示 Yuxi 登录框。

如果独立登录失败，先确认输入的是 Yuxi 本地密码，而不是旧 OA 密码；再检查用户是否被删除、是否仍在登录锁定期，或尚未完成管理员密码设置。
