# 入院申请表自动化填报 SOP（本地项目版）

> **核心原则**：
> - **Skill** = 标准作业流程 (SOP) + 业务判断规则 + 知识库使用规范。
> - **数据源优先级（硬性）**：① **产品事实表**（`query_product_facts`，一次查询返回全部基础事实）→ ② **项目知识库检索**（`query_kb` 等，仅用于事实表缺项与 B 类循证证据）→ ③ 用户提供的材料。**严禁公网搜索、模型记忆编造任何客观事实。**
> - **宿主要求**：可读写 Word 文件（沙盒内用 terminal + python-docx）；会话已启用知识库技能（含 `query_product_facts` 工具）。

---

## 🚀 启动自检清单 (Startup Checklist — 10 秒内必须完成)

在打开、解析或编辑任何文档之前，按顺序验证：

- [ ] **Check 1 (文件)**: 申请表模板文件是否存在？（否 → 立即停止并要求用户提供）
- [ ] **Check 2 (药名)**: 目标药品名称是否已由用户明确指定？（否 → 立即停止并询问药品名，**不调用任何文档工具**）
- [ ] **Check 3 (事实表连通)**: 调用 `query_product_facts(product_name=目标药名)` 是否返回事实数据或"产品存在"信号？（返回"会话未启用产品知识库" → 停止并告知用户需在会话中启用产品知识库）
- [ ] **Check 4 (知识库锁定)**: 调用 `list_kbs` 能否唯一锁定「产品知识库」的 `kb_id`？（用于缺项兜底检索）
- [ ] **Check 5 (产品消歧)**: 事实表/知识库中该药名是否唯一对应一个剂型、厂家、规格？（存在多个候选 → **立即询问用户**确认具体款项，不得自行猜测）

> **【硬性阻断】只有上述 5 项全部 PASS 后，方可进入模板分析与填写阶段！**

# Phase 0: 预检与准入硬闸门

### Gate 0 — 药品身份明确性检查 (BEFORE ANY TOOL CALL)
```text
在调用任何文档分析、文件编辑、检索工具之前：
确认用户已明确给出目标药品名称。若没有 → 立即停止并询问。
不要打开表格去猜要填哪个药；不要从文件名、目录上下文推断药名。
```
- 若用户仅发送了表格文件但未说具体药名，直接回复："请问您需要为哪一款具体药品填写入院申请表？请提供药品名称。"并停止执行。

### Gate 1 — 数据源连通与初探（替代原外部 MCP 自引导）
1. 调用 `query_product_facts(product_name=药名)`：
   - 返回事实数据 → 记录产品在事实表中的**标准 product_id**（可能与用户口语名称有出入，以表内为准）；
   - 返回"暂无该产品" → 用 `list_kbs` + `search_file` 在产品知识库中确认该产品是否存在；知识库也没有 → 停止，告知用户知识库中无此产品资料；
2. **禁止公网回退**：数据源不可用时立即停止（无事实表 + 无知识库 = 不填写），绝不使用 web_search 或模型记忆补充客观事实。

### Gate 2 — 产品身份消歧
事实表或知识库中同一药名对应多个剂型（如"缓释片"与"注射液"）、多个厂家或多规格时，**立即向用户确认**：
"该产品存在以下几种剂型/厂家/规格：[列表]，本次申报具体是哪一款？" 明确后方可进入 Phase 1。

# Phase 1: 快速模板扫描 (Quick Template Scan)

1. **确认表单概况**：包含几张表格、是否有《药品遴选评分表》；
2. **关键栏位与表尾红线排查**：浏览表头、字段标签及**表尾"注"**；若表尾注明"禁止填写商品名或生产企业名"，立即记录此禁令（**表格红线 > 通用规则**）；
3. **建立字段清单 (A/B/C 三分类)**：
   - **A 类（客观产品事实）**：通用名、剂型、规格、包装、批准文号、生产企业、MAH、医保类别、挂网价格、用法用量、适应证、贮藏、有效期等（有唯一客观答案）；
   - **B 类（证据型生成内容）**：引进理由、必要性、优效性、安全性、经济性、指南推荐（需基于客观证据整理）；
   - **C 类（人工审批职责）**：申请人签名、科室意见、药事会审核、药学部门复评得分、院领导批示（**一律跳过不填，保留原样空白**）。

# Phase 2: 取证 —— 事实表优先，一次查全 (Evidence Gathering)

### 1. 【首选】产品事实表一次性查询（A 类基础事实）
```text
query_product_facts(product_name="{确认的产品通用名}")
```
- **一次调用返回该产品全部事实项**（通用名、剂型、规格、包装、成份、性状、用法用量、有效期、批准文号、生产企业、贮藏、适应证等），直接作为 A 类字段的**权威来源**；
- **禁止**再对 A 类字段逐个走向量检索——事实表里有的值必须采用事实表；
- 注意区分"全部规格"与分装量取值，按模板栏位语境选用；
- 返回值同时带来源文件信息，写入报账时引用。

### 2. 缺项兜底（仅限事实表没有的项）
事实表未收录的 A 类字段（常见：医保类别、挂网/采购价格、MAH）：
- `query_kb(kb_id, "{通用名} 医保类别 挂网价格 采购价 ...")` 检索；
- 检索结果必须经 `find_kb_document` / `open_kb_document` 回**原文**核对（数字、单位、上下文），**严禁凭切片断章取义或编造**；
- 仍查不到 → 留空并计入"证据缺失待补"，**绝不填 "TBD"、"未知"、"—"**。

### 3. B 类循证依据检索
- `query_kb(kb_id, "{通用名} 临床指南推荐 推荐意见 推荐等级 循证等级 临床有效率 不良反应发生率 经济性日治疗费用 依从性")`；
- **关键结论核对原文（高精核验，杜绝断章取义）**：
  - **不良反应发生率**（如 2.04%）：核验总评价样本量与发生率真实上下文，**严禁自行捏造数字**；
  - **临床指南评级**：核对原文是否确有"（推荐强度:1, 证据等级:A）"；**若原文未注明级别，严禁擅自补充 A 级**；
  - **挂网价格**：核实数字与计价包装单位（元/盒）。

# Phase 3: 工作副本生成与精确写回 (Writeback)

### 1. 物理复制工作副本
- 将 `模板.ext` 复制为 `模板-filled.ext`（扩展名与格式完全一致）；同名已存在则改为 `模板-filled-{药品名}{规格}.ext`，**绝不覆盖既有成果**。后续编辑只针对工作副本。

### 2. 写回机制（沙盒 python-docx 流程）
用 terminal + python-docx 打开工作副本，按以下铁律写表格：
- **先读后写**：先遍历表格读取行列结构、合并单元格范围与单元格现值，建立"标签 → 值槽"映射后再写；合并单元格的值槽可能在非首列，写入前用短标记探针验证落点，**任何写回后必须逐格回读**确认落笔；
- **大段作答行常是整行合并格**（如"申请理由"）：必须**连标签一起写**进锚点格（如 `适应症一线推荐用药：是。…`），防止覆盖行标签；
- **「评价」栏常仅 1 汉字宽**：此类栏只填 `1` 或 `0`（评分表按"1=符合/0=不符合"约定）；依据类长文本改附对照说明或写入申请报告，避免竖排撑破版面；
- **残留值必须逐格清**：同列中凡属上一药品的分值/文号/价格一律核对清除（包括看似通用的 `0`/`1`）；合计须"按格求和"验证；
- **行高保持自适应**：`row.height_rule = WD_ROW_HEIGHT_RULE.AT_LEAST`，不得改成 EXACT；
- **复选框字符**：模板常混用 `(` 与 `□` 表示同一空框（勿把 `(` 误判为已勾选）；统一改写为 `□`（未选）/ `☑`（已选），回读时核对数量；
- **字体先读后写**：读已填格的字体字号并照抄（医院自制表常为仿宋_GB2312 / 12pt 小四，不要死套宋体 10.5）；行距 1.15~1.25，段后 2pt 左右。

### 3. 依据规范撰写并填入
参考 [`references/writing-guide.md`](references/writing-guide.md) 与 [`references/approved-example.md`](references/approved-example.md)：
- **A 类字段**：格式规范（规格三要素写全、包装写全两层、价格带单位）；无价格且用户未提供 → 留空待补；
- **A/B 类口径差异**：`生产企业` 栏取说明书【生产企业】全称（**常与上市许可持有人 MAH 不同，属受托生产，不要混填**），MAH 写入"其他"栏；用户口头指定厂家则以其为准，并把简称补全为营业执照全称；
- **B 类申请理由**：
  - 栏内有具体追问 → **逐条作答**；
  - 通用大格 → **六段式论证**（政策性→必要性→优效性→安全性→经济性→依从性→指南推荐）；
  - **反幻觉红线**：无直接对比研究不声称"优于同类"；无竞品价格不声称"低于同类"；无证据的段落直接省略，绝不强行拼凑；
- **评分表**：仅填明确属于"申请科室自评"的得分；"药学部复评"、"专家评审"、"一票否决"一律跳过；自评无证据时不擅自填 0 分；
- **C 类字段**：不写入任何字符，保持模板原貌空白。

### 4. 排版美学硬性规范
- **逢点必分段**：遇序号（`1.`）、小标题（`一、`）、条目（`•`）必须拆为独立段落，严禁用分号/空格挤压成一大块；
- **模块化小标题与关键词加粗**：大段综合内容用小标题（如 `【不良反应】`），段首小标题加粗；
- **二级细项结构化**：临床研究按 `• 研究类型`、`• 研究人群`、`• 主要结果` 分行呈现；
- **自适应防裁切**：写回长文本后行高必须自适应，确保打印无截断。

# Phase 4: 回读质检与标准报账 (Verify & Report)

1. **数值回读校验**：用 python-docx 重新读取工作副本，核对实际落盘文字与计划写入值完全一致，排除落点错位；
2. **红线排查**：确认 C 类字段保持空白、表尾禁填项未被误填；**旧药残留值排查**——模板常沿用上一药品已填值（采购单价/批准文号/商品名/规格等），逐一核对清除任何不属于本次目标药品的残留；
3. **排版核查**：结构级校验——逐单元格统计段落数、加粗 run 数、行距与行高规则是否达标；
4. **原文件保护确认**：确认原始模板文件未被修改；
5. **结构化交付报账**：

```text
================ 药品准入申请表填报报告 ================
【任务概要】
- 目标药品：[已核实的产品通用名（事实表 product_id）]
- 输出文件：[模板名-filled.docx]
- 数据源：产品事实表（query_product_facts）+ 产品知识库检索（kb_id）[严格无公网回退]
- 事实表覆盖：A 类字段 X/Y 项来自事实表，Z 项检索兜底

【字段填报统计】
- 已成功填写 (Filled): X 项
- 规则跳过 (Skipped): Y 项 (C类人工审批栏位; 表尾禁填红线项)
- 证据缺失待补 (Missing): Z 项 (事实表与知识库均未查得，已保持空白)
- 来源冲突 (Conflicts): 0 项

【核心安全与质检】
- 准入闸门：Phase 0 (药名确认 + 事实表连通 + 产品消歧) 均已通过
- 模板安全：已建立独立工作副本，原始模板未被修改
- 回读校验：PASS (所有修改格回读吻合，未发生错位)
- 排版校验：PASS (长文本完整，无截断)

【重点说明事项】
1. [跳过原因说明，如触发表尾注红线、C类签名保留空白等]
2. [若有待补字段，提示用户后续人工核实]
=======================================================
```
